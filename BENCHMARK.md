# Спецификация бенчмарка MAPF-HD

Бенчмарк запускает реализации на одинаковых сценариях, проверяет планы и сравнивает makespan, computation time и success rate.

## Вход

| Карта | Размер | Целевых агентов | Статические препятствия |
| --- | --- | ---: | --- |
| `toyota-env1` | 14×7 | 2 | Нет |
| `toyota-env2` | 14×7 | 2 | Два блока 2×3 |
| `toyota-env3` | 35×21 | 12 | Нет |
| `toyota-env4` | 35×21 | 12 | Группы колонн, 90 клеток |
| `pillars-70x42` | 70×42 | 12 | 24 столба 3×3 |
| `aisles-100x60` | 100×60 | 12 | 24 стеллажа 4×22, проходы 3 клетки и поперечный проход 4 клетки |

Геометрия и цели Toyota взяты из `run_env1.py`–`run_env4.py`. Цели малых карт находятся в двух углах одной стороны, остальных — по периметру.

Сценарий задаёт карту, старты всех агентов, цели и seed. ID имеет вид `toyota-env4-d090-s003`. Генерация воспроизводима, точные входы сохраняются в JSON. Плотность = число всех агентов / число проходимых клеток.

| Параметр | Значение |
| --- | --- |
| `--scenario` | Один ID или сохранённый JSON |
| `--map` / `--pool` | Одна карта / весь пул |
| `--density` | По умолчанию 50, 75, 90, 95% |
| `--seeds N` | Seed 0…N−1, по умолчанию 10 |
| `--timeout` | По умолчанию 180 с на попытку |
| `--solver` | `phans` или `NAME=module:function`, можно повторять |
| `--baseline` | База сравнения, по умолчанию `phans` |
| `--out` | Новая папка результатов, по умолчанию метка времени в `benchmark-results/` |

Полный профиль содержит 240 сценариев на реализацию.

## Реализации и проверка

Адаптер `solve(instance)` получает `benchmark.maps.Instance`. Цели `instance.map.goals` соответствуют первым агентам `instance.starts`. Остальные агенты — перемещаемые блокеры. Результат `frames[t][i] = (x, y)` содержит всех агентов в исходном порядке и кадр `t=0`. Допустимы `None` и незавершённая трасса. Для случайных решений используйте `instance.seed`.

Каждая попытка выполняется в отдельном процессе. Встроенный PHANS загружается из коммита `a82ed819d37932ff845e170805f41e24c82e550b` с `max_loop=300` и `a_star_max_iter=-1`.

Валидатор проверяет старты, число агентов, границы, стены и конфликты. Агент может ждать или перейти в соседнюю по стороне клетку, пустую в начале такта. Позиции в конце такта должны быть уникальны.

## Метрики

| Метрика | Расчёт |
| --- | --- |
| Makespan | Первый такт одновременного достижения всех назначенных целей |
| Computation time | Секунды подготовки внутри решателя и получения полного плана |
| Success rate | Валидные решения в пределах лимита / все попытки |

Импорт модулей, проверка, сохранение и визуализация исключены из замера. При таймауте поле времени содержит лимит. Статусы — `solved`, `timeout`, `unsolved`, `invalid`, `crash`.

В HTML и boxplot абсолютные время и makespan сравниваются на одинаковых сценариях, решённых всеми выбранными реализациями. Для одного решателя используются его успехи. В `summary.csv` абсолютные медианы рассчитаны по успехам каждого решателя.

Относительное сокращение = `100 × (baseline − кандидат) / baseline` для каждого общего решения, затем медиана. Нулевой знаменатель даёт пустое значение. Изменение success rate сохраняется в относительных процентах и процентных пунктах. Также считаются общие, новые и потерянные решения.

## Результат

HTML содержит выбор карты, сводную таблицу по каждой карте и плотности, графики и встроенный просмотр парных планов. В таблице для каждого алгоритма показаны решённые задачи из общего числа, success rate и медианы времени и makespan. Для модификации отдельно показаны число общих решений с PHANS, сокращение времени и makespan на общих решённых сценариях и исходы пар. Положительное сокращение означает улучшение.

| График | Данные |
| --- | --- |
| `runtime_box` | Абсолютное время по реализациям, секунды |
| `makespan_box` | Абсолютный makespan по реализациям, такты |
| `success` | Доля решённых задач по плотности на выбранной карте |
| `success_heatmap` | Доля и число решений для каждой пары «карта × плотность» |
| `paired` | Ускорение и изменение makespan на общих решённых сценариях |

Boxplot показывает наблюдения, медиану, Q1–Q3 и усы до 1,5 IQR. HTML работает без сервера.

| Файл | Содержимое |
| --- | --- |
| `report.html` / `report.md` | HTML-отчёт / табличная сводка |
| `results.csv` | Каждая попытка, статус, метрики, причина отказа |
| `summary.csv` | Сводные абсолютные и относительные метрики |
| `comparison.csv` / `pairs.csv` | Агрегированное / посценарное сравнение с baseline |
| `plots/` | Общие PNG и SVG |
| `maps/<ID>/` | CSV, Markdown и четыре графика одной карты |
| `run.json` | Версии, параметры, лимиты и хеш набора |
| `instances/` / `logs/` / `plans/` | Входные JSON / логи / сжатые трассы |

## Использование

Требуются Python 3.11/3.12 и Git с историей закреплённого коммита. Установка — `conda env create -f environment.yml` и `conda activate phans`. Для существующего Python нужны `numpy==2.3.5` и `matplotlib==3.9.4`. Команды выполняются из корня клона, `RUN` обозначает папку результатов.

~~~sh
python -m benchmark list
python -m benchmark run --scenario toyota-env4-d090-s003
python -m benchmark run --map toyota-env4 --density 90 95 --seeds 3
python -m benchmark run --pool --solver phans --solver candidate=team_solver:solve --out RUN
python -m benchmark report RUN
python -m benchmark report RUN --map toyota-env4 --solver candidate --solver-label "candidate=Моя модификация" --out NEW_RUN
python -m benchmark plot RUN --kind runtime_box makespan_box --map toyota-env4
python -m benchmark replay RUN --scenario toyota-env4-d090-s000 --solver candidate
~~~

`report` принимает фильтры `--solver`, `--map` и `--density`; выбор кандидата автоматически добавляет baseline. Отчёт сравнивает PHANS с одной модификацией. `--solver-label NAME=LABEL` задаёт читаемое имя модификации в таблице, графиках и плеере; если его не задать, будет показан ID решателя. Отчёт создаёт папку `replays/` с парным плеером для каждого сценария, где есть результаты обеих реализаций. Построение отчёта использует сохранённые CSV, JSON и трассы и не запускает решатели повторно; если трасса не сохранена, плеер покажет её отсутствие.

## Парный плеер

Парный плеер доступен в отчёте через фильтр результата и выбор сценария; каждый плеер также сохраняется отдельным HTML-файлом в `replays/`. PHANS слева, модификация справа. Такт, пуск/пауза и скорость общие. Короткий план удерживает последний кадр, открытие происходит на паузе.

Сохранённые трассы используются повторно, отсутствующие получаются отдельной попыткой. `--rerun` пересчитывает обе, `--timeout` задаёт бюджет. Исходные измерения сохраняются. При наличии `sources/` исполняется проверенный по хешам архив, иначе текущий адаптер. Статус и отсутствие трассы показываются в плеере; отсутствие трассы одной стороны не блокирует другую.

Проверка — `python -m unittest discover -s tests -v`.
